Histórico de alterações e decisões técnicas
08/09/2026 — v1.11
Coluna "Venc. Original" na tabela para clientes em acordo feat
  • Nova coluna "Venc. Original" exibe a data de vencimento da cobrança antes da renegociação
  • Setor usa essa data para calcular os 60 dias de cancelamento sem precisar abrir o HubSoft
  • Coluna azul para clientes em acordo, "—" para inadimplentes regulares
  • Filtrável e ordenável
08/09/2026 — v1.10
Renegociados: data da cobrança original no badge feat
  • Badge "em acordo · venc DD/MM" exibe a data de vencimento da cobrança original (antes da renegociação)
  • Setor visualiza quando o débito real começou para calcular os 60 dias de cancelamento
  • Coluna "Venc. Original" adicionada no export XLSX
  • Subquery correlacionada via renegociacao_fatura_pendente para obter MIN vencimento original
08/09/2026 — v1.9
Fix: cobranças com fatura paga não contam como débito aberto fix
  • Cobranças antigas com recebido=false mas fatura paga eram incorretamente contadas como débito em aberto
  • HubSoft historicamente não atualizava cobranca.recebido ao pagar a fatura — dado inconsistente desde 2024
  • Fix: LEFT JOIN fatura + filtro f.data_pagamento IS NULL — se a fatura foi paga, a cobrança é ignorada
  • ultimo_pagamento agora usa COALESCE(cb.data_pagamento, f.data_pagamento) para capturar pagamentos em ambas as tabelas
  • Caso JOSE JONES (id_cs 73016): cobrança set/2024 aparecia porque recebido=false, mas fatura paga em 03/09/2024
08/09/2026 — v1.8
Clientes em acordo (renegociação ativa) incluídos na dashboard feat
  • Renegociação cancela a cobrança original e cria nova com vencimento futuro — cliente some da lista indevidamente
  • UNION query: inclui serviços com fatura nova de renegociação ativa e não paga (renegociacao_fatura_nova)
  • Badge azul "em acordo" no nome do cliente e fundo diferenciado na linha
  • Coluna "Em Acordo" no export XLSX
  • Ordenação: inadimplentes regulares primeiro, em acordo ao final
08/09/2026 — v1.7
Correção: cobrança por serviço em vez de fatura aglutinada fix
  • Query migrada de fatura para cobranca — cada cobrança é vinculada ao id_cliente_servico correto, independente de fatura aglutinada
  • Clientes com "Fatura Separada: Não" não terão mais serviços secundários aparecendo como "nunca pagou"
  • Critério de inadimplência ajustado: cobrança VENCIDA há > 90 dias sem pagamento (antes era último pagamento há > 90 dias)
  • Elimina falsos positivos de serviços novos com fatura futura mas data de habilitação antiga
08/09/2026 — v1.6
Checkbox de troca de titularidade por linha feat
  • Checkbox "Titular" na última coluna para marcar clientes com troca de titularidade
  • Estado persiste em localStorage (chave inadim_titul_v1) — sobrevive a "Atualizar" e reload
  • Linhas marcadas ficam com fundo âmbar e badge "troca titular" no nome
  • Botão "Ocultar trocas (N)" aparece quando há marcados — filtra sem perder o registro
  • Coluna "Troca Titular" incluída no export XLSX
08/09/2026 — v1.5
Filtro 90 dias para clientes sem histórico de pagamento fix
  • Clientes com ultimo_pagamento IS NULL (nunca pagaram) entravam na lista independente da data de habilitação
  • Serviços habilitados há menos de 90 dias e sem pagamento não configuram "débito em aberto há 90 dias"
  • Fix: outer WHERE adicionou condição data_habilitacao < CURRENT_DATE - INTERVAL '90 days' quando ultimo_pagamento IS NULL
  • Implementado na API — sem impacto nos clientes que já pagaram alguma vez
08/09/2026 — v1.4
Auto-refresh no carregamento da página feat
  • ALL_DATA baked no HTML (snapshot de 04/09/2026) causava data de atualização travada
  • Página agora carrega com ALL_DATA vazio e chama refreshData() automaticamente no load
  • Timestamp inicial alterado de data hardcoded para "Carregando dados..."
  • Dados sempre frescos ao abrir — sem necessidade de clicar em "Atualizar"
07/09/2026 — v1.3
Correção: pagamentos parciais excluídos do valor em aberto fix
  • Faturas com data_pagamento IS NOT NULL (mesmo parcialmente pagas) eram contadas como "em aberto"
  • O HubSoft considera essas faturas quitadas — a query estava divergindo do saldo real
  • Fix: valor_em_aberto agora soma apenas faturas com data_pagamento IS NULL
  • Validado com cliente MICHERLANE (cobranças em aberto = 0 no HubSoft, agora 0 na dash também)
07/09/2026 — v1.2
Perfil Suspensão: fallback para padrão do sistema feat
  • Clientes sem id_perfil_suspensao preenchido no banco mostravam "—"
  • O HubSoft aplica "Perfil Padrão 5 Dias (NOVO)" como padrão quando o campo está nulo
  • Fix: COALESCE(ps.descricao, 'Perfil Padrão 5 Dias (NOVO)') na query
07/09/2026 — v1.1
Auditoria completa e reescrita da query de dados data
  • Source alterada: tabela cobranca → tabela fatura (reflete saldo real do cliente)
  • JOIN corrigido: perfil_suspensao estava joinando em forma_cobranca por engano
  • CASE situação corrigido: descrição "Ativo" não existe no banco — IDs reais: 11=Ativo, 9=Cancelado, 12/13/14/50=Suspenso
  • WHERE movido: cláusula WHERE estava após GROUP BY (erro de sintaxe SQL)
  • Lógica de 90 dias: usa MAX(data_pagamento) por serviço — último pagamento registrado na fatura
  • Resultado: ~23.5k contratos, R$4.55M — versus R$4.51M na versão estática de 04/09

Botão de refresh dinâmico adicionado feat
  • Novo endpoint GET /api/inadimplencia/data na API NetOps

  • Timeout configurado: 130s (query pesada — base com +600k faturas)
  • Cards e contadores tornados dinâmicos com IDs no HTML
