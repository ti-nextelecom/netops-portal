📋 Backlog — GPON Diagnóstico

18/09/2026Feature
Histórico de pings — acumulação de testes por dispositivo
Após cada ping, o resultado é salvo em memória (até 10 por dispositivo na sessão). Exibido abaixo do painel de resultado com timestamp, qualidade, min/avg/max/jitter/perda. Permite acompanhar variação de latência ao longo do tempo sem recarregar a página.
18/09/2026Feature
Auto-repeat 10/10 — repetição automática de pings
Botão "▶ Auto N/10" no painel de resultado. Aguarda o cooldown de 40s do OLT-Cloud, exibe contagem regressiva de 5s e dispara o próximo ping automaticamente. Repete até 10/10. Botão "⏹ Parar" disponível a qualquer momento. Intervalo real entre testes: ~45s.
18/09/2026Feature
ONT_MODEL_CONFIG — suporte multi-modelo para ping e WiFi
Arquitetura por modelo: mapa explícito para TP-Link (XC220-G3, XX530v, XX530vV2, XX535, EX141, EX521, EC220-G5), Huawei (HG8145V5, EG8145X6, HG8245 e demais), ZTE (F6600P, F670L) e TDTC (HG15, HG9). Configurações: interface de ping, max_rep por firmware, modo WiFi (split_band vs unified), campo RSSI por modelo. Fallback por prefixo serial + default global.
18/09/2026Fix
WiFi NULL e contagem 0 dispositivos — XX535
XX535 retornava Padrão="NULL" (string literal) causando exibição "WiFi NULL" e contagem 0 nas bandas 2.4/5.8GHz. Fix: Padrão "NULL" normalizado para string vazia; dispositivos com Padrão vazio contabilizados como 2.4GHz (fallback).
18/09/2026Fix
IP oculto XX535 — normalização campo IP nos dispositivos conectados
XX535 retorna campo IP como objeto {param: "...", hidden: true} em vez de string. Fix: IP normalizado para null quando não é string. Limitação do ACS/OLT-Cloud para este modelo — IP não disponível via TR-069.
17/09/2026Feature
Ping de host interno via ONT
Botão 📶 por dispositivo: inicia ping direto via ONT (TR-069 Device.IP.Diagnostics.IPPing) para medir latência/perda LAN. Exibe min/avg/max/jitter/perda com classificação de qualidade (Estável/Instável/Muito Instável/Sem resposta). Cooldown de 40s entre pings (rate limit OLT-Cloud). Suporte multi-modelo via ONT_MODEL_CONFIG.
17/09/2026Fix
OLT_MAP — mapeamento de OLTs corrigido
Mapeamento estava invertido: 30XXX=PQS (era MUSSURUNGA), 31XXX=MUSSURUNGA (era PQS). Corrigido em GPON Diagnóstico e CGNAT Diagnóstico.
17/09/2026Fix
Detecção de banda — Conexão "Other" tratada como WiFi
Dispositivos com Conexão="Other" (ex: iPhone, Samsung com MAC aleatório) apareciam como "Ethernet". Corrigido: Conexão "Other" é tratada como WiFi na exibição de banda.
17/09/2026Fix
RSSI WiFi — limiares e cores separados do sinal óptico
Limiares RSSI WiFi separados dos limiares do sinal óptico GPON. Novos limiares WiFi: ≥ -70 dBm → Verde (Bom) | -71 a -77 dBm → Amarelo (Regular) | ≤ -78 dBm → Vermelho (Ruim).
17/09/2026Melhoria
Dispositivos Conectados — RSSI e Banda
Tabela enriquecida com dados do grupo "Dispositivos WiFi" do ACS (MAC, Padrão, RSSI). Banda exibe padrão WiFi (ac, ax, n, etc.). RSSI com código de cor (verde/amarelo/vermelho).
17/09/2026Fix
IP WAN — extraído da sessão PPPoE real
Campo "IP WAN (Internet)" agora lido da tabela "WAN PPPoE" do ACS (IP da sessão PPPoE conectada). Fallback: IP da tabela BNG (display access-user username). ONTs que não reportam ExternalIPAddress agora exibem o IP corretamente.
17/09/2026Fix
BNG — sessão PPPoE não exibia dados
display access-user username no NE40E retorna formato tabela (não key-value). Corrigido: regex parseia a tabela, extrai IP → chama display access-user ip-address para obter todos os detalhes da sessão (plano, velocidade, interface, uptime).
17/09/2026Fix
WiFi Vizinhos — scan não retornava dados
Endpoint corrigido: dados em chart_data["2.4GHz"].networks e ["5GHz"].networks (não network_list/results). Status "Complete" (capital C) detectado via .toLowerCase(). signal_dbm e channel são strings → parseInt(). Canal recomendado calculado localmente (API retorna null).
17/09/2026Melhoria
Memória ONU — uso de RAM
Novo campo "Memória" exibe % de uso + MB (usado/total) via Device.DeviceInfo.MemoryStatus.Total e .Free. Código de cor: verde <70%, amarelo 70-85%, vermelho >85%.
17/09/2026Melhoria
Largura de canal WiFi
Novo campo "Largura canal" nas bandas 2.4GHz e 5.8GHz via Device.WiFi.Radio.1/2.OperatingChannelBandwidth (ex: 20MHz, 40MHz, 80MHz). Depende do ONT reportar o campo.
17/09/2026Feature
Análise de Canal WiFi — scan de redes vizinhas
Botão "Escanear redes vizinhas" dispara scan TR-069 neighboring_wifi na ONT via OLT-CLOUD. Exibe todas as redes detectadas com canal, largura, sinal e banda. Identifica sobreposição com o canal atual e recomenda canal sem interferência (1, 6 ou 11 para 2.4GHz).
